## 已定位的问题

1. **下载源选择不当。** 容器 pip 配置里存在清华镜像和九章云 Nexus，且 `PIP_SOURCE=nexus` 会强制选择内网 Nexus。检查时没有正在下载权重或依赖的进程。官方 PyPI 可访问；查询到 `nvidia-cuda-nvcc` 的版本信息返回正常。之后安装依赖应显式指定 `--index-url https://pypi.org/simple`，不要依赖容器里叠加的默认 pip 配置。权重不需要重下。
2. **Talea 原 SGLang fork 不认识模型架构。** 原环境启动时报 `glm5_next` 未注册。上游 SGLang 源码已包含 `Glm5NextForConditionalGeneration`，所以后续测试使用了独立验证环境，没有覆盖原 Talea 环境。
3. **DeepGEMM 要求较新的 NVCC。** 首次加载在 DeepGEMM 检查处因系统 NVCC 12.8 小于要求的 12.9 而退出。设置 CUDA 13.2 `nvcc` 后，`deep_gemm.get_num_sms()` 返回 132，证明这一项已绕过。
4. **JIT 编译器没有找到 CCCL。** 上游 SGLang 启动时自定义 all-reduce JIT 编译报 `fatal error: nv/target: No such file or directory`。头文件实际存在于上述 FlashInfer CCCL 路径。SGLang 源码提供 `--disable-custom-all-reduce` 参数，可回退到 NCCL。
5. **验证环境并非自包含。** `/dev/shm/glm53-venv` 的 Python 指向 Talea 的解释器，`pyvenv.cfg` 设置 `include-system-site-packages = true`，并未把 Talea 的所有包都带进自身 `sys.path`。两个主要问题：
   - CUDA 13 的 `libnvJitLink.so.13` 位于 Talea 环境的 `nvidia/cu13/lib`，不在 glm53 验证环境里。测试证明把该目录加进 `LD_LIBRARY_PATH` 后，PyTorch `2.13.0+cu130` 可以导入。
   - 启动日志仍报找不到 `libnvJitLink.so.13`，说明之前 nohup 命令中的库路径没有可靠地传入进程，或命令构造时变量展开/后台 shell 环境丢失。后续应先在**同一条启动 shell 中**执行 `env | grep LD_LIBRARY_PATH` 和 `python -c 'import torch; print(torch.__version__)'`，成功后再从该 shell 启动服务；必要时将环境变量写入独立脚本文件再执行，避免 SSH 多层引号导致变量丢失。
6. **附带告警。** TorchCodec 报缺少 FFmpeg 动态库，但目前没有证据表明它是此次退出根因。不要先花时间处理，除非新的主错误明确指向 TorchCodec。

## 建议接手步骤

先通过 SSH 确认当前状态。可在具备外连权限的终端运行：

```bash
ssh -p 30027 root@120.220.102.21
```

检查进程、端口和最后的错误：

```bash
pgrep -af 'sglang.launch_server|sglang.srt.managers.scheduler' || true
ss -ltnp | grep 30000 || true
tail -100 /dev/shm/glm53-server.log
```

确认单进程的 Python 依赖搜索路径。下面的路径都应该加到本次启动环境，尤其 `LD_LIBRARY_PATH` 中必须含 CUDA 13 的 `lib` 目录：

```bash
CUDA_PKG=/dev/shm/talea-venv/lib/python3.10/site-packages/nvidia/cu13
CCCL=/dev/shm/glm53-venv/lib/python3.10/site-packages/flashinfer/data/cccl/libcudacxx/include
export PATH="$CUDA_PKG/bin:/dev/shm/glm53-venv/bin:$PATH"
export CUDA_HOME="$CUDA_PKG" CUDA_PATH="$CUDA_PKG" CPATH="$CCCL"
export PYTHONPATH="/dev/shm/sglang-main-src/python:/dev/shm/glm53-venv/lib/python3.10/site-packages:/dev/shm/talea-venv/lib/python3.10/site-packages:/dev/shm"
export LD_LIBRARY_PATH="$CUDA_PKG/lib:/dev/shm/talea-venv/lib/python3.10/site-packages/nvidia/cuda_runtime/lib:/dev/shm/talea-venv/lib/python3.10/site-packages/nvidia/nvjitlink/lib:/dev/shm/talea-venv/lib/python3.10/site-packages/nvidia/cublas/lib:/dev/shm/talea-venv/lib/python3.10/site-packages/nvidia/cusparse/lib:/dev/shm/talea-venv/lib/python3.10/site-packages/nvidia/cusolver/lib:/dev/shm/talea-venv/lib/python3.10/site-packages/nvidia/cufft/lib:/dev/shm/talea-venv/lib/python3.10/site-packages/nvidia/cudnn/lib:/dev/shm/glm53-venv/lib/python3.10/site-packages/nvidia/nccl/lib:/dev/shm/glm53-venv/lib/python3.10/site-packages/nvidia/nvshmem/lib:/usr/local/nvidia/lib64:/usr/local/nvidia/lib"
export FLASHINFER_DISABLE_VERSION_CHECK=1 SGLANG_DEEPGEMM_PDL=0
command -v nvcc
nvcc --version
python -c 'import torch; print(torch.__version__, torch.cuda.is_available())'
python -c 'import deep_gemm; print(deep_gemm.get_num_sms())'
```

若上述 Python 预检通过，再启动。前台启动更便于保留完整错误和退出状态：

```bash
python -m sglang.launch_server \
  --model-path /dev/shm/GLM-5.3-Flash \
  --tp-size 8 \
  --host 0.0.0.0 \
  --port 30000 \
  --disable-cuda-graph \
  --disable-custom-all-reduce
```

看到模型就绪且 `ss -ltnp | grep 30000` 有监听后，再从另一个终端验证：

```bash
curl -fsS http://127.0.0.1:30000/health
curl -fsS http://127.0.0.1:30000/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{"model":"/dev/shm/GLM-5.3-Flash","messages":[{"role":"user","content":"你好，请用一句话介绍自己。"}],"max_tokens":64}'
```

健康检查和短生成请求都成功后，才算完成推理验证。记录完整启动命令、服务日志里的最终启动标记、模型响应和生成速度。

## 注意事项

- 前面几次通过 SSH 后台启动的尝试均失败，没有形成一个已知正常运行的服务；接手时先查进程和日志。

- 工作只在这台 H100 容器的 `/dev/shm` 临时环境里进行，没有提交代码改动。模型目录和验证环境均会在容器重启时消失。
