## 1. 主要修复

| 问题 | 修复与验证重点 |
|---|---|
| 事件已入库但执行中断，重启后意图可能丢失 | 持久化规范事件，PENDING 有限批次轮转恢复；忙实例不会阻塞后面的回收；旧 ABANDONED 保持终态 |
| 事件 ID/节点 ID 混用，旧 ADD 可能越过新回收 | 按合作商、业务内容、租约和事件时间校验；用已接受回收作为旧 ADD 的屏障 |
| 地址/租约变更可能先覆盖旧地址，无法正确摘流 | 先保存 PendingUpdate，旧端点停止后原子切换；新旧地址均保留占用，回收优先 |
| 停止失败仍可能释放容量，重试绕过退避 | 必须收到 STOPPED；保存回收意图、稳定操作 ID、租约检查和停止重试 |
| LOST、外部停服、角色/模型漂移与 Router 门禁导致虚假 SERVING | 重新探测运行身份和 Router 可路由状态，合法恢复、关闭 readiness 或摘流 |
| Planner 缩容超过单轮限制、双节点档位可能缺 P | 限制变更数量、正确扣减角色计数、遵守容量上限和排空宽限；双节点保留 1P1D |
| Pull 只比较相邻快照，无法纠正 Push 漂移 | 每轮与当前意图对账；保留忙节点与回收优先级，保护拉取期间的新事件 |
| 不完整 HTTP 列表可能误判所有节点消失 | 严格完整快照契约；拒绝缺失/null/分页/尾随数据；409 释放失败保留重试 |
| 安装超时反复恢复、并发启动和残留子进程 | 超时终态清凭据；拒绝覆盖 INSTALLING；取消代际校验；真实 Linux 进程组清理及 PID 复用保护 |
| 认证重定向、浏览器旧请求干扰新会话 | 控制接口拒绝 HTTP 重定向；401 和跨会话异步结果隔离；失联节点排除在服务中计数之外 |

配置模板补齐 SSH 上线入口及 P 的 bootstrap 端口。构建打包 benchmark 客户端，完整测试入口包含安装器测试。历史文档增加版本说明，当前入口收敛为两份手册。

## 4. 保留的边界

- Planner 仍为固定档位，实时指标供观察，尚未接入自适应配比。
- static 释放仅停止服务并归还 Talea 容量记录，不销毁平台容器；真实合作商接口需单独验证。
- 当前适配受控 Ubuntu/CUDA/Python/H100 组合；全新无缓存镜像、多卡、RDMA、大规模集群与整机 reboot 未验收。
- Router 异常 PD draining 门禁可以被识别，但完全自动恢复仍有边界。
- 运行中 bootstrap 升级需要有计划地摘流、停服和重启；更新控制节点的安装源不会替换已经运行的工作节点进程。
- 本轮未对真实 GPU 服务做断网、强杀和在途回收故障注入；相关故障路径的证据来自单元/集成模拟与 Linux 真实子进程测试。
